# 要素分割與抽離指南 (Split & Extract Elements)

> 把**一則完成的提示詞**拆回可讀的分段，再按需求移除指定類別的要素，
> 留下乾淨骨架；抽出的要素則回收為可再利用的模組。
>
> 本篇是 [mp-prompts-merge-001.md](mp-prompts-merge-001.md) 的**逆向操作**——
> 合併篇教「把模組插進基底」，本篇教「把成品拆回模組」。

| 欄位 | 內容 |
| --- | --- |
| 檔名前綴 | `mp-` = modular prompt（模組化提示詞） |
| 完整範例 | [prompts/mp-element-extraction-example.md](prompts/mp-element-extraction-example.md) |
| 本例抽離目標 | UI 要素、人物要素（目標可依需求替換） |
| 本例保留目標 | 場景／關卡要素、風格要素 |
| 適用時機 | 要純場景版、要無人物版、要把某段要素拿去複用、要把散亂提示詞整理可讀 |

---

## 1. 為什麼要抽離 (Why)

- **產出乾淨變體** — 「不含 UI」的美術輸出、「不含人物」的場景圖，都靠抽離達成
- **呼應人物三版本規則** — 主技能的「無人物版本」前置作業就是移除人物要素（見 [SKILL.md](../SKILL.md) 的 People Versions Rule）
- **要素可複用** — 抽出的人物模組、UI 模組可送進 [mp-prompts-merge-001.md](mp-prompts-merge-001.md) 的 `[PROMPT]` 插槽
- **散亂提示詞變可讀** — 即使不抽離，光是分段整理就讓替換與修改有明確邊界

### 分析能力反哺合併 (Analysis Informs Merging)

**懂得如何正確分析、分割要素，也就能更容易判斷該如何合併提示詞。**

兩者是同一套判斷的正反兩面：

| 分析時要判斷的 | 合併時的對應判斷 |
| --- | --- |
| 這段屬於哪個類別？（UI／人物／關卡／場景／風格） | 插進來的模組屬於哪個類別？該放在哪一段？ |
| 哪些句子依賴彼此的指代？（拆開會斷裂） | 前後段是否自足？有無跨槽指代會被插入內容撞破？ |
| 哪些要素定位模糊、可留可刪？ | 哪些內容基底要掌握、哪些交給模組？ |
| 同類內容散落幾處？ | 構圖指令只由基底宣告一次，避免重複宣告 |

**具體連動：**

- 能看出「人物外觀」與「人物動作」是可分離的兩層 → 合併時就能判斷**服裝該寫在基底還是模組**（兩邊同時宣告會互相打架）
- 能看出「UI 要素」不依賴場景句 → 合併時就知道**場景可以整段替換**而不影響 UI
- 能看出某要素定位模糊 → 合併時就會**讓它獨立成句**，而不是塞進詞組中間讓它更難判斷

> 換言之：**抽離是練習「看出結構」，合併是運用「看出結構」**。
> 分析得越準，插槽開在哪、模組怎麼切就越有把握。

---

## 2. 三階段流程 (Three Stages)

**關鍵：先整理、後抽離。** 不要在原始混雜狀態下直接動手刪——容易漏、容易斷指代。

| 階段 | 做什麼 | 不做什麼 |
| --- | --- | --- |
| **一、原始內容** | 照原樣保留，作為對照基準 | 不動任何字 |
| **二、分段整理** | 去除外包裝標籤、分行、分段、調整順序 | 不改用字、不改句構 |
| **三、要素抽離** | 移除指定類別的要素，其餘逐字保留 | 不重寫、不補寫 |

```text
[階段一 原始內容]
      ↓  分段整理（結構層：排版、順序）
[階段二 可讀分段]
      ↓  要素抽離（內容層：移除 UI / 人物）
[階段三 場景骨架]  +  [抽出的 UI 模組]  +  [抽出的人物模組]
```

### 階段二允許動什麼

- ✅ **排版**：分行、分段、空行
- ✅ **順序**：把散落的同類內容歸攏到同一段
- ✅ **去包裝**：移除 `Caption:`、`Prompt:` 這類外包裝標籤（非提示詞本體）
- ❌ **措辭**：用字、詞組、句構一律不動

### 階段三允許動什麼

- ✅ **移除**：目標類別的要素整段或整句拿掉
- ❌ **補寫**：不為了讓句子變通順而重寫其餘部分

## 3. 要素分類 (Element Categories)

以完整範例的實際內容為準：

| 類別 | 內容 | 本例片段 |
| --- | --- | --- |
| **UI 要素** | HUD、頂欄、圖示、計時器、指示連線、收集物道具 | `A black top bar shows a flame icon, a snowflake icon and the timer 00:58`、`red and blue diamonds sit on the platforms` |
| **人物要素** | 角色外觀、角色專屬動作與裝備 | `an adult man with short red hair and a red-orange shirt with a flame emblem hangs from a rope and`、`an adult man ... pushes` |
| **關卡／動線要素** | 可通行路徑、互動機構、機制連動 | `swings across a gap`、`a big brass lever, a giant gear that lowers a wooden bridge` |
| **場景要素** | 建築、背景、靜態道具 | `clockwork tower interior of brass gears...`、`A huge clock face fills the background`、`a small steam pipe hisses on the left` |
| **風格要素** | 光線、線條、色調、整體質感 | `Warm amber light and bold outlines give the tower a lively mechanical look` |

> **抽離目標不固定**：本例抽「UI＋人物」留其餘；若要做純 UI 稽核，反過來抽其餘留下 UI 即可。
> 重點是**先分類、再決定抽誰**，而非死背本例的組合。

## 4. 規則 (Rules)

### 規則 1：最小修改，不用全新描述重新詮釋

- 階段二、三都只做**結構與移除**，不改措辭
- **若你認為確有重新描述的必要，請額外提供一個版本**，不得取代最小修改版
- 判斷：原始提示詞品質良好時，最小修改即可 → **不另附重述版**（本例即此情況）

### 規則 2：先整理，後抽離

- 分段完成後再刪，才能一眼確認「刪了什麼、還剩什麼」
- 未分段就動手，容易殘留半句、漏掉重複出現的目標

### 規則 3：模糊要素可保留，但必須獨立成行

- **無法判斷是否為需要移除的目標時，可以保留**
- 但該要素**必須自成一行／一段**，讓結構可讀性明確——之後要刪或要留，定位得到
- 本例的 `red and blue diamonds` 即屬此類：定位不明，在此歸為 UI 道具而抽離（見範例檔的專節說明）

### 規則 4：依實際內容處理，不套固定模板

- 本例原始內容結構良好（一句一要素、段落分明），所以**只需分行分段**即可
- **實務上很多提示詞散亂混雜**：風格句夾在人物與背景之間、UI 散落多處、同類內容重複出現
- 這時階段二必須**一併調整結構與順序**——分析時依照**實際內容**判斷歸類與段落，不假設原文有序

### 規則 5：抽離不等於丟棄

- 抽出的 UI 模組、人物模組都要**另存**，作為可複用素材
- 需要時透過 [mp-prompts-merge-001.md](mp-prompts-merge-001.md) 的插槽重新組回

## 5. 反模式 (Anti-patterns)

| ✗ 反模式 | 後果 | ✓ 正確做法 |
| --- | --- | --- |
| 直接重寫成全新描述 | 失去與原始的對照，無法稽核改了什麼 | 最小修改；必要時**另附**重述版 |
| 在未分段的原文上直接刪 | 難以確認有沒有漏、容易刪到一半 | 先走完階段二再抽離 |
| 模糊要素擠在句子中間 | 之後想刪／想留都定位不到 | 獨立成行（規則 3） |
| 抽離後留下斷裂指代 | `from it`、`pushes` 找不到主詞，畫面出現懸空物件 | 抽離後檢查殘句的指代是否仍成立 |
| 抽離後硬把殘句補成通順 | 實質上就是重新描述，違反最小修改 | 先判斷是否為**標籤概念**——是則無需更動；必要時允許**最小修改**的調整；或**另附**重述版（見下方三層判斷） |
| 預設原文有結構 | 散亂提示詞照抄分段，同類內容仍分散 | 階段二依實際內容重排（規則 4） |

### 關於殘句的取捨 (Handling Residual Fragments)

最小修改可能留下語法不完整的殘句（例如 `On the lower floor, swings across a gap.`）。
**不要一律硬補通順**，依序判斷三層：

| 層級 | 判斷 | 做法 |
| --- | --- | --- |
| **1. 是否為標籤概念？** | 殘句雖缺語法，但作為**標籤／要素片段**語意仍清楚（如 `swings across a gap` = 動線標籤，`a big brass lever` = 機關標籤） | **無需更動**——提示詞本來就容納標籤式片段 |
| **2. 是否有必要調整？** | 缺語法已影響判讀（指代斷裂、可能產生懸空物件） | 允許**最小修改**的調整——只補必要承接，不重寫既有內容 |
| **3. 下游需要完整語法？** | 需要通順句子（如交給講求語法的流程） | **另附**重述版，不動最小修改版 |

**本例判定：** `On the lower floor, swings across a gap.` 與
`On the upper right floor, a big brass lever, a giant gear that lowers a wooden bridge.`
都屬於**層級 1（標籤概念）**——前者是動線標籤、後者是機關與連動標籤，
即使缺主詞，生成時仍可正常理解 → **維持原樣不動**。
若要語法完整，見範例檔第 4 節的另附版本。

> **核心：** 標籤概念不是錯誤，是提示詞的合法形態。
> 「補成通順」的衝動多半來自把提示詞當文章看——判斷前先確認**這句是要被當句子讀，還是當標籤用**。

## 6. 與其他規則的關係

- **[SKILL.md](../SKILL.md) — People Versions Rule（人物三版本規則）**：人物要素抽離是「無人物版本」的前置作業
- **[mp-prompts-merge-001.md](mp-prompts-merge-001.md) — 合併／插槽技法**：本篇的逆向操作，抽離所得模組可插入 `[PROMPT]` 插槽
  - **反過來也成立**：能正確分析分割要素，就更容易判斷該如何合併——類別歸屬、指代依賴、職責邊界是兩邊共用的判斷（見第 1 節「分析能力反哺合併」）
- **排版規則（分行與空行）**：階段二即套用分段分行原則，價值在**人類閱讀性**與**可替換性**
- **[dy-dynamic-prompts.md](dy-dynamic-prompts.md) — 動態提示詞**：抽離後的骨架若要批量變化，可再套 `{a|b|c}` 取代欄位

## 7. 送出前檢查清單 (Checklist)

- [ ] 是否只動了排版、順序與移除，**未改任何措辭**？
- [ ] 是否已先分段、後抽離？
- [ ] 模糊要素是否**獨立成行**且判斷理由可說明？
- [ ] 抽離後的殘句：是否先判斷為**標籤概念**（是→不動）？必要時才做**最小修改**？需要完整語法時是否**另附**重述版？
- [ ] 殘句的指代是否仍然成立？有無懸空物件？
- [ ] 被抽離的要素是否已另存為模組？
- [ ] 若有重新描述，是否為**額外**版本、未取代最小修改版？
- [ ] 分類與段落是否依**實際內容**判斷，而非套用固定模板？
