# 數字前置詞規範 / Numeric Prefix Specification

數字前置詞是**排序控制工具**，不是分類工具。分類交給路徑與檔名語意，只有「必須按順序呈現」的檔案才使用數字前置。

---

## 使用時機

### ✅ 可以使用

- 教學文件章節（`010-` 安裝、`020-` 設定、`030-` 部署，讀者需依序閱讀）。
- 有法定或流程順序的文件（RFC、審批流程、milestone 文件）。
- 必須在檔案總管中固定顯示順序的少數特殊檔案（如特定順序的配置片段）。

### ❌ 不得使用

- 一般主題文件、README、指南、參考資料——它們沒有固定順序。
- 為了「讓檔案總管整齊」而批量加上 `001-`、`002-`、`003-`。
- 預期日後會頻繁插入新內容的序列。

---

## 為什麼禁止密集序號

對無排序需求的檔案加上連續序號（`001-`、`002-`、`003-`）會造成：

1. **無法在中間插入**：新增檔案只能排到末尾或重編全部號碼。
2. **錯誤排序**：部分檔案本質上不該被數字排序，強加序號會誤導讀者以為存在順序。
3. **被迫改名**：調整順序時必須變更既有檔名，破壞外部連結與 git 歷史追溯。

---

## 間隔策略

确有排序需求時，**以 10 為單位**分配，預留插入空間：

```text
010-install.md
020-configuration.md
030-deployment.md
```

- 需要在安裝與設定之間插入新章節 → 使用 `015-`，無需改動任何既有檔名。
- 介於中間的補充內容 → 使用 `012-`、`018-` 等，仍保有擴充彈性。

> [!NOTE]
> 底數選擇可依專案密度調整（10、100 皆可），但**必須預留插入間距**；`001-`、`002-` 這種相鄰序號等同於零間距，不可接受。

---

## 同組共用序號

**沒有明確先後順序的檔案可以擁有相同的數字前置詞**，組內依字母序排列：

```text
010-overview.md
010-requirements.md
010-limitations.md
```

三者同屬「前期說明」階段且彼此無順序，共用 `010-`；檔案總管中以字母序顯示即可。

---

## 決策樹

```text
檔案需要被排序嗎？
├─ 否（預設）→ 不加數字前置，靠路徑分類 + 檔名語意
└─ 是 → 以 10 為單位分配（010、020、030...）
        ├─ 同組成員無先後 → 共用同一序號
        └─ 日後可能插入 → 預留間距，禁止相鄰序號
```
