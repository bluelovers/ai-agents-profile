# 雙語註解格式規範 (Bilingual Comment Format)

當註解需要使用**雙語**（繁體中文 + 英文）時，請遵循以下格式規範。

## 格式選擇

| 格式 | 適用場景 | 範例 |
|------|----------|------|
| **單行格式** | 簡短說明 | `/** 說明 / Description */` |
| **多行格式** | 詳細說明或翻譯較長時 | `/** 說明\n * Description */` |

## 語言順序

- **中文在前，英文在後**
- 使用 `/` 分隔，或分行書寫
- 禁止「英文 + 英文」的假雙語

```typescript
// ✅ 正確：單行格式
/** 是否成功 / Whether successful */
const isActive = true;

// ✅ 正確：多行格式
/**
 * 取得分組鍵的函式
 * Function to get grouping key
 *
 * @param item - 要分組的元素 / Element to group
 */
getKey?(item: T, index: number, arr: T[]): any

// ❌ 錯誤：假雙語（兩行都是英文）
/**
 * Process data
 * Process data
 */

// ❌ 錯誤：英文在前、中文在後（順序顛倒）
/**
 * English description / 繁體中文說明
 */
```

## 彈性捨棄雙語原則 (Flexible Bilingual Omission)

當雙語造成**閱讀障礙**或**內容過長**時，保留最清晰的一種語言即可，無需強制雙語。

本節的另一面是**彈性保留雙語 (Flexible Bilingual Retention)**（見本節末尾「變體」子節）——
兩者**一體兩面、本質相同**：都只保留真正有雙語價值的部分，差異僅在**取捨方向**的微小不同。

**例外：技術術語的雙語標註仍應保留**（如 `聯合類型 (Union Type)`、`快取 (Cache)`）。

**判定基準 (Quick Check)：** 看雙語中的**英文部分**——不懂英文、只理解簡單單字的人，是不是也知道？

- **知道**（如 `Code`、`Problem` 這類簡單詞）→ 英文對中文讀者未提供新資訊：屬可捨棄的雙語，二擇一保留（見「無意義雙語」）
- **不知道**（需具備英文程度才懂，如 `Cache`、`Union Type`）→ 英文是理解與搜尋的入口：保留雙語

**範例參考 (Examples)：**

| 雙語／單語 | 英文部分判定 | 結果 |
|------|------|------|
| `技能說明文字 / description text` | **知道**——`description`、`text` 皆為常見簡單詞，只懂簡單單字的人也知道 | **捨棄**英文 → `技能說明文字` |
| `解毒標記 / cure-poison flag` | **不知道**——領域複合詞，非日常簡單詞，需具備英文程度才懂 | **不變** → `解毒標記 / cure-poison flag` |
| `行動後硬直`（原本無英文） | **有價值/不知道**——缺此英文時，英文讀者沒有對照詞可理解與搜尋 | **新增**雙語 → `行動後硬直 / post-action stiff` |

> 三例對應三種結局：**捨棄**（英文無價值）、**不變**（英文有價值）、**新增**（原本缺少有價值英文對照）——
> 判定入口都是同一個：看英文部分，不懂英文、只理解簡單單字的人是不是也知道？

> ⚠️ 例外：「有特殊意圖的雙語」（見子項目二，如 `增益 / Up`）不受此基準影響——
> 即使英文是簡單單字，只要中英彼此不對應、捨棄任一方即失去雙向搜尋，仍須保留。

**譯名不唯一的術語 (Variant Translations)：** 部分技術術語的中文譯名不唯一
（如 `Cache` → 快取 / 緩存 / 緩衝），中文本身即帶歧義——只留中文時，不同讀者會用不同譯名搜尋而比對不到。
這類術語兩種做法皆可，唯獨**不可只保留中文譯名**：

- **必要性雙語**：`快取 (Cache)` — 譯名 + 英文錨點，兩種語言的讀者都能對上
- **僅保留英文**：`Cache` — 以英文為唯一稱呼，從根源避免譯名分歧

| 情境 | 建議做法 |
|------|---------|
| 短句、術語名稱已自明 | 可省略另一語言 |
| 雙語合併後超過一行或內容過長且可讀性下降 | **先縮小雙語範圍**（僅術語保留雙語）；仍過長再選擇最清晰的語言捨棄另一語言 |
| 技術術語首次出現 | **必須保留雙語標註**，格式：`中文 (Term)` |
| 已有完整雙語 | 保留，不主動刪除 |

```typescript
// ✅ 短句已自明，可只保留一種語言
/** 是否啟用 */
const isEnabled = true;

// ✅ 雙語過長時，選最清晰的語言
/**
 * 當使用者處於非活躍狀態且訂閱已到期，系統將自動封存帳號並寄送通知信
 */

// ✅ 技術術語仍須保留雙語
/**
 * 使用快取 (Cache) 避免重複查詢，並透過聯合類型 (Union Type) 表達多種回傳格式
 */
```

### 無意義雙語（可捨棄）

同時滿足下列三個條件時，雙語**無意義**，只需保留一種語言：

| 條件 | 說明 |
|------|------|
| **無歧義** | 中英語意完全相同，不會因語言不同而產生不同解讀 |
| **無技術術語** | 不含需要保留原文比對的技術術語 |
| **無搜尋比對問題** | 保留一種語言即可滿足以關鍵字搜尋、比對程式碼的需求 |

常見的無意義雙語：

| 範例 | 處理方式 |
|------|---------|
| `程式碼 / Code` | 二擇一保留 |
| `問題點 / Problem` | 二擇一保留 |
| `正確做法 / Correct fix` | 二擇一保留 |

```typescript
// ❌ 錯誤：無意義雙語（無歧義、無技術術語、無搜尋比對問題）
/** 程式碼 / Code */

// ✅ 正確：二擇一保留
/** 問題點 */
/** 正確做法 */
```

### 子項目二：有特殊意圖的雙語（不可捨棄）

當中英詞彙**彼此不對應**——「中文」不會被翻譯為「英文」，「英文」也不會被翻譯為「中文」時，
雙語為**必要**：便於理解另一語言的讀者，也便於以任一語言搜尋比對。

```typescript
// ✅ 必須雙語：「增益」不會被翻譯為 up，up 也不會被翻譯為「增益」
/** 增益前綴 / Up prefix */

// ✅ 同理，保留雙語以利理解與雙向搜尋
/** 增益 / Gain */
/** 增益 / Up */
```

### 變體：彈性保留雙語 (Flexible Bilingual Retention)

與「彈性捨棄雙語原則」**一體兩面**：本質相同——都只保留真正有雙語價值的部分；差異僅在**取捨方向**。

| | 彈性捨棄雙語 (Omission) | 彈性保留雙語 (Retention) |
|---|---|---|
| 出發點 | 已有中文＋英文 → 判斷能否刪掉其中一種 | 內容逐段拆解 → 判斷哪些資訊單位需要雙語 |
| 判斷方向 | 由整體往下裁 | 由局部往上組 |
| 典型情境 | 修剪既有的長雙語註解 | 撰寫新註解，決定哪個詞需要英文 |

**核心規則 (Core Rule)：**

> **逐項判斷哪些資訊需要雙語，只保留真正有雙語價值的部分。**
> 雙語不是整份內容的固定格式，而是依照各資訊單位的理解、辨識、搜尋用途局部保留，其餘自然使用單一語言。

- ❌ 不採用「只要這份內容需要雙語，就整段中文＋英文」
- ❌ 也不採用「既然英文不一定需要，就盡可能全部刪掉」

**四條規則：**

1. **最小必要範圍**：雙語縮小到真正需要的資訊單位，而非整句、整段雙語化——
   `使用快取 (Cache) 避免重複查詢。` 僅 `快取 (Cache)` 雙語，其餘維持中文
2. **不要求完整對照翻譯**：不需要「中文一句、英文一句」的鏡像翻譯；中文為主的段落自然混入必要英文即可——
   `使用快取 (Cache) 儲存 API response，避免相同 request 被重複送出。`
3. **同句可混合單語與雙語**：中文、英文、中英對照可共存於一句，不強制整句統一語言——
   `啟用 Cache 後，使用者資料先從快取取得，未命中才執行 API request。`
   （英文為主的註解同理：僅在必要處加入中文對照，不逐句翻譯）
4. **有額外價值才雙語**：英文具備搜尋／辨識／對照價值 → 保留（子項目二 `增益 / Up`、譯名不唯一 `Cache`）；
   僅為直譯且無額外價值 → 單語（子項目一 `程式碼 / Code`）。
   **「有無價值」的判定一律回到判定基準**：看英文部分，不懂英文、只理解簡單單字的人是不是也知道？

**雙語保留判定表：**

| 情況 | 建議 |
|------|------|
| 中文已足夠表達 | 僅中文 |
| 英文已足夠表達 | 僅英文 |
| 英文只是中文直譯、無額外價值 | 省略英文（見「無意義雙語」）——**仍須先過判定基準** |
| 中文只是英文直譯、無額外價值 | 省略中文——**仍須先過判定基準** |
| 技術術語需保留原文 | 局部雙語，格式：`中文 (Term)` |
| 英文是搜尋／辨識關鍵字 | 雙語或僅英文（見子項目二、譯名不唯一） |
| 一句中只有某個詞需要英文 | 只讓該詞雙語 |
| 整段都需要對照 | 才使用完整雙語 |
| 雙語造成內容過長 | **先縮小雙語範圍**（保留術語局部雙語），仍過長才捨棄一種語言 |

> ⚠️ 「只是直譯、可省略」**不能憑感覺判斷**——上表兩列仍須先過**判定基準**：
> 看雙語中的英文部分，不懂英文、只理解簡單單字的人是不是也知道？
> - **知道**（`Code`）→ 英文無額外價值：屬二擇一，省略英文或省略中文皆可（視主語言而定）
> - **不知道**（`Cache`）→ 英文有額外價值：**不可逕刪任一方**——應保留雙語，或依「譯名不唯一」僅保留英文

## JSDoc 標籤雙語格式

JSDoc 標籤（如 `@param`、`@returns`、`@throws` 等）中的描述也可以使用雙語格式：

```typescript
/**
 * 取得使用者資料
 * Get user data
 *
 * @param userId - 使用者識別碼 / User identifier
 * @param options - 選項配置 / Options configuration
 * @returns 使用者資料 / User data
 * @throws 當使用者不存在時拋出錯誤 / Throws error when user not found
 */
function getUserData(userId: string, options?: GetUserOptions): UserData {
    // ...
}
```

**格式說明：**
- 在 `-` 後面使用 `描述 / Description` 格式
- 中文在前，英文在後，使用 `/` 分隔
- 適用於所有 JSDoc 標籤： `@param`、`@returns`、`@throws`、`@see` 等
